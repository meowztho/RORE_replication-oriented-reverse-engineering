# CoreReplica User Vision

## Product intent

CoreReplica is an improved reference-reconstruction plugin that helps an agent study an existing product, identify useful behavior and UX patterns, define a distinct target product, implement it through the target repository's canonical architecture, verify the actual result, and prepare/release it without conflating those responsibilities.

The plugin should feel like Core-First Governance applied to reference-driven product development: small always-loaded routing, detailed procedures only JIT, single owners, no parallel truth, evidence matched to claims, and explicit correction/release boundaries.

## Desired outcomes

A capable fresh agent using CoreReplica should be able to:

- study a reference product clean-room style from allowed sources;
- preserve source/evidence provenance and uncertainty;
- separate what the reference does from what the new product should do;
- turn reference traits into explicit `adopt | adapt | reject | inspiration-only` decisions;
- find/reuse the target repository's existing owners before adding architecture;
- implement through existing contracts rather than create a clone-specific parallel architecture;
- keep implementation progress distinct from verified completion;
- verify real user/external behavior on the closest practical surface;
- compare functional/structural parity without treating a heuristic score as release authority;
- research complaints/market opportunities without inventing reviews or claims;
- create a distinct brand/launch package without making brand a second Design-System owner;
- prepare a release fully while stopping at the exact consequential transition until approval is present;
- continue after context loss by rediscovering current repository/project truth and loading only the required authorities/skills.

## Non-goals

CoreReplica is not:

- a universal cloning engine;
- a source-code extractor, decompiler, private-API copier, credential harvester or scraping framework;
- a replacement for Core-First Governance;
- a second project architecture owner;
- a general test runner, deployment platform or legal compliance engine;
- an acceptance system that trusts builder self-report;
- a mandatory 8-step or 11-step pipeline.
