# RORE v0.4.2 Handoff

RORE v0.4.2 preserves the v0.4.1 domain-neutral reconstruction boundary and adds three bounded reverse-engineering evidence hardenings without adding a new owner or downstream dependency.

The live boundary is:

```text
reference target
→ evidence acquisition and reconstruction
→ Evidence + Findings + Paths + reference-native Models
→ coverage / contradictions / unknowns
STOP
```

Removed active responsibilities: Product, Design-as-target-translation, Build, replica Verification/Parity, Market/Brand/Launch and Release. Useful reverse-engineering methods from those lanes were absorbed into Reconstruction or Evidence Review.

The user-supplied snapshots `replica-skill-main.zip` and `reverse-skill-main.zip` were re-inspected before the migration. The audit specifically restored/strengthened stable surface/flow identity, edge-state reconstruction, hypothesis/negative-evidence discipline, deadlock replanning, bias/context-pollution checks, protocol/mobile/web/differential analysis and perturbation-as-causal-instrument.

Do not reintroduce APC/project-compilation coupling into RORE. Downstream consumers may use RORE output, but RORE does not adapt Reference Truth for them.

v0.4.2 adds only:
- current-state observation-path liveness when a live claim has concrete stale/frozen/cached/replayed/disconnected-path risk, with the reverse guard that identical static observations alone do not prove failure;
- fresh/anti-anchored Evidence Review where feasible, while still reviewing the existing evidence graph read-only;
- explicit semantic-to-low-level descent for static/binary reconstruction when source/decompiler abstractions cannot discriminate a material hypothesis.

## Domain neutrality
RORE is domain-neutral. Games are a stress-test domain, not a primary target. Route from the unresolved knowledge/evidence boundary; domain-specific profiles are optional JIT method bundles only.
